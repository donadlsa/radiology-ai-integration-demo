Pattern #1: DICOM SR Series Description Rejected by PACS Worklist Filter

4 occurrences DICOM
Mayo Clinic Guy's & St Thomas' Cleveland Clinic
Root Cause
Different PACS vendors filter their reading worklist by Series Description. Our AI engine sends SR with Series Description 'AI Analysis Report' but some PACS expect specific strings like 'AI_FINDINGS' or match on department-specific patterns.
Current Workaround
Manual update of SR Series Description in routing config per customer. Takes ~30 min per incident.
Recommended Fix
Add configurable SR Series Description template per customer in the integration configuration. Default to 'AI Analysis Report' but allow override during onboarding.
Impact if Fixed
Eliminates ~4 tickets/month, saves 2 hours/month of Tier 2 engineer time.
Engineering — Integration Config
Effort: 2 sprint points
Fix Requested — JIRA ENG-4521

Pattern #2: HL7 Facility Code Changes After PACS Maintenance

3 occurrences HL7
Charité Berlin St Vincent's Sydney
Root Cause
When customers perform PACS upgrades or maintenance, the sending facility code in MSH-4 sometimes changes. Our interface engine does exact-match validation and rejects messages from unrecognized facilities.
Current Workaround
Manually add new facility code as alias in interface engine. P1 incident each time — average 3.5 hour resolution.
Recommended Fix
1) Implement facility code alias mapping (accept multiple codes per customer). 2) Add proactive config validation check that runs after any customer-reported maintenance window.
Impact if Fixed
Prevents P1 incidents. Estimated 10.5 hours saved per occurrence.
Engineering — Interface Engine
Effort: 3 sprint points
Approved — Sprint 2026-06-A

Pattern #3: FHIR Token Expiry During Weekend/Holiday

5 occurrences FHIR
4 customers affected
Root Cause
OAuth2 tokens for FHIR server access have 24-48 hour TTL. Token refresh runs on a schedule but fails silently when the customer's identity provider has maintenance windows on weekends. No alert fires until FHIR submissions start failing.
Current Workaround
Manual token refresh via API call. Tier 1 can resolve in 15 minutes but only after customer reports the issue.
Recommended Fix
1) Add proactive token health check — verify token validity every 4 hours with a test request. 2) Alert on token refresh failure, not just submission failure. 3) Implement automatic token retry with exponential backoff.
Impact if Fixed
Eliminates 5 tickets/month. Converts reactive weekend incidents to proactive weekday maintenance.
Engineering — Auth & Platform
Effort: 5 sprint points
Under Review — Product Team
